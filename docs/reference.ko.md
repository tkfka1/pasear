# pasear 상세 안내

[빠른 시작](../README.ko.md) · [English](reference.md)

## 여러 호스트

제어할 Paseo 호스트마다 pasear를 설치합니다. 같은 플러그인은 사이드바에 하나로 표시되며 Paseo가 제공하는 상단 호스트 선택기에서 관리할 대상을 바꿉니다. 서버 상태 옆에 선택한 호스트 이름이 표시됩니다. **Start server**는 그 호스트의 플러그인 프로세스 안에서만 MCP 포트를 열며, 설정·연결 비밀키·OAuth 승인·접근 범위도 호스트별로 독립적입니다.

A에서 서버를 켠 뒤 B로 전환해도 A 서버는 계속 실행됩니다. B의 시작·중지·연결 해제는 A에 영향을 주지 않습니다. 호스트를 바꾸면 해당 호스트의 화면과 저장된 설정을 불러오며, 저장하지 않은 초안은 다른 호스트로 옮기지 않습니다. 선택한 호스트가 끊기면 해당 호스트를 다시 연결해야 하며 다른 호스트로 요청을 보내지 않습니다.

외부 채팅에는 호스트별 공개 HTTPS MCP 주소를 각각 커넥터로 등록하고 인증합니다. Paseo 화면의 호스트 선택은 기존 채팅 연결의 대상을 바꾸지 않습니다. LB도 각 공개 주소를 해당 호스트로 고정 연결해야 하며 여러 호스트에 무작위 분산하지 않습니다. 각 호스트의 독립 네트워크에서는 같은 8787 포트를 사용할 수 있고, 같은 네트워크 네임스페이스를 공유하는 데몬끼리는 서로 다른 포트가 필요합니다.

같은 머신의 LB는 루프백으로 연결할 수 있습니다. LB가 다른 머신이면 **네트워크 · 0.0.0.0**을 선택하고 LB 대상에는 이 호스트의 접근 가능한 IP를 사용합니다. `0.0.0.0`은 바인드 주소이며 접속 주소가 아닙니다. 자동 터널 생성은 하지 않습니다.

인증은 **OAuth Authorization Code + S256 PKCE** 하나입니다. OAuth 브라우저에서 연결 비밀키를 확인하고, 인증된 Paseo 화면에서 소유자가 권한을 승인해야 합니다. 비밀키를 채팅 본문이나 커스텀 요청 헤더에 넣지 마세요. 비밀키는 MCP 접근 토큰으로 사용할 수 없습니다.

## LB 설정

MCP 요청은 루트(`/`)와 기존 `/mcp`에서 받습니다. OAuth에는 별도의 인증·메타데이터 경로가 필요합니다. 전용 MCP 도메인이라면 모든 경로를 플러그인 포트로 전달하는 구성이 간단합니다. TLS 인증서와 도메인은 사용자 환경에서 설정합니다.

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header Authorization $http_authorization;
    proxy_read_timeout 60s;
}
```

필요 경로: `/`, `/mcp`, `/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource`, `/.well-known/oauth-protected-resource/mcp`, `/authorize`, `/token`, `/register`, `/revoke`, `/oauth/flow/…`.

TLS는 LB에서 종료해도 됩니다. OAuth 주소는 저장된 공개 HTTPS 주소에서 결정하며 전달된 Host 헤더에서 추측하지 않습니다. LB 로그인 화면이 이 경로를 가로막으면 웹 채팅이 연결할 수 없습니다. `/healthz`는 프로세스 생존 확인이며 실제 MCP 호출 성공을 의미하지 않습니다. 기본 OAuth rate limit은 프록시 뒤의 클라이언트를 하나의 IP로 집계할 수 있으므로 다수 사용자 배포 시 별도 설계가 필요합니다.

## OAuth 승인

1. 웹 채팅에 공개 MCP 주소를 등록하고 OAuth 연결을 시작합니다. 클라이언트 등록은 **DCR/자동 등록**을 선택합니다. CIMD는 현재 구현하지 않았습니다.
2. 열린 브라우저에 pasear 메인 화면에서 복사한 **Connection key**를 입력합니다. 키가 틀리면 Paseo에 승인 요청도 나타나지 않습니다. 키 확인 후 확인 코드와 돌아갈 주소를 표시하고 대기합니다.
3. Paseo의 **pasear 메인 화면**에서 같은 코드와 주소인지 확인합니다. 앱 이름은 요청자가 등록한 값이므로 그 이름만으로 신뢰하지 마세요.
4. 허용할 프로젝트·워크스페이스·에이전트를 선택합니다. 승인하면 선택한 범위에서 작업 요청·메시지 전송·중단을 함께 허용합니다. 프로젝트·워크스페이스 전체 허용은 앞으로 생기는 하위 항목도 포함합니다.
5. **Approve connection**을 누르면 웹 채팅의 브라우저 창이 자동으로 돌아갑니다.

비밀키 확인을 시작한 요청은 5분 후, 발급된 코드는 1분 후 만료됩니다. 비밀키를 5회 잘못 입력하면 해당 요청은 잠기며 웹 채팅에서 다시 시작해야 합니다. 자동 등록과 비밀키 확인은 최종 승인이 아닙니다. 사용자에게 보이는 권한은 작업 제어 하나입니다. OAuth 내부에서는 `paseo:read`, `paseo:write`, `paseo:cancel`을 함께 요청하며, 일부만 요청한 새 연결은 `invalid_scope`로 거절합니다. 앱 이름과 ID에 따른 권한 예외는 없습니다. 알 수 없는 권한값은 거절합니다. 액세스 토큰은 최대 1시간, 연결과 갱신 토큰은 최초 승인부터 30일 유효합니다. 갱신 토큰은 한 번 사용하면 교체되고 재사용 시 해당 연결 전체를 차단합니다. **Disconnect**는 토큰을 차단하며 이미 접수된 에이전트 작업을 취소하지 않습니다.

워크스페이스 제한은 MCP API에서 조회·호출할 수 있는 대상의 범위입니다. 에이전트의 파일·명령 실행 샌드박스는 해당 공급자의 설정을 따릅니다. 작업 권한 요청은 Paseo에서 승인합니다.

## 웹 채팅 설정

네 서비스의 등록 메뉴와 공통 승인 절차는 [빠른 시작의 채팅 연결](../README.ko.md#채팅-연결)을 참고하세요. OAuth 연결을 시작하면 위의 비밀키 확인과 소유자 승인을 완료해야 합니다.

- **Claude:** 추천으로 표시되는 게시된 ID(CIMD) 대신 자동 등록(DCR)을 선택합니다. 조직 계정은 관리자가 먼저 커넥터를 추가해야 할 수 있습니다.
- **ChatGPT:** 새 화면은 Plugins에서 등록합니다. 기존 Apps 화면을 사용하는 계정은 사용자 설정 또는 워크스페이스 설정의 **Apps → Create**에서 OAuth 연결·도구 스캔 후 생성합니다. 생성 권한은 계정과 워크스페이스 정책을 따릅니다.
- **Gemini:** [개발자 모드](https://gemini.google.com/devmode)의 **Authentication → Client Authentication Configuration**에서 **Dynamic Client Registration**을 선택할 수 있습니다. 수동 클라이언트 등록은 필요하지 않습니다.
- **Grok:** 등록 후 서버가 제공하는 도구를 검색해 대화에서 사용합니다. 조직 계정은 관리자의 커넥터 구성이 먼저 필요할 수 있습니다.

메뉴가 보이지 않거나 연결에 실패하면 README에 연결된 각 서비스의 공식 안내와 현재 계정 조건을 확인하세요. 고정 API 키 인증이나 커스텀 요청 헤더 대신 pasear의 OAuth 승인 절차를 사용합니다.

## 작업 제어

커넥터를 연결하고 해당 채팅에서 선택한 뒤, 평소처럼 짧게 말하세요. 정해진 호출 키워드는 없으며 도구 사용은 웹 채팅이 판단합니다. 요청 예시와 각 도구의 역할은 아래에서 확인할 수 있습니다.

| 말하기 예시 | 동작 |
| --- | --- |
| “프로젝트 목록 보여줘” | 접근 가능한 상위 프로젝트 조회 |
| “상점 프로젝트의 워크스페이스와 작업 보여줘” | 해당 프로젝트 안의 허용된 워크스페이스·에이전트 조회 |
| “Paseo에서 뭐 하고 있어?” | 최근 작업 목록과 상태 조회 |
| “상점에서 로그인 오류 조사해줘” | 워크스페이스를 찾아 새 작업 접수 |
| “어디까지 됐어?” | 같은 채팅의 작업 상태·최근 활동·변경 파일·마지막 답변을 한 번에 조회 |
| “테스트도 해줘” / “이어서 해줘” | 같은 에이전트에 후속 지시 |
| “잠깐 기다렸다 결과 알려줘” | 최대 20초 대기 후 조회. 시간이 지나도 작업은 계속 실행 |
| “그 작업 멈춰줘” | 현재 실행 중단 요청. 세션·기록·변경 파일은 보존 |
| “보관한 로그인 작업의 원본 세션 가져와줘” | 같은 제공자 세션을 가져오거나 복구. 호스트 전체 허용 연결에서 사용 |
| “로그인 작업 기록을 Codex 새 에이전트에게 넘기고 테스트해줘” | 기록을 요약·인계해 별도 세션 생성 |

사용자가 내부 ID나 재시도 키를 입력할 필요는 없습니다. AI가 이 채팅에서 받은 `agentId`를 이어 쓰며, 이름을 지정하면 정확히 일치하는 고유 작업을 찾습니다. 새 채팅에서는 작업 이름이나 ID로 대상을 알려주세요. 다른 채팅의 마지막 작업을 자동으로 선택하지 않습니다. 같은 이름이 여러 개이거나 대상이 불명확하면 선택을 요청합니다.

새 작업의 `title`은 생략할 수 있습니다. 워크스페이스는 허용된 항목이 하나일 때 자동 선택하며, 실행 공급자가 하나이고 기본 모델이 명확할 때 `provider`도 생략할 수 있습니다. 공급자만 지정해도 해당 공급자의 기본 모델을 사용합니다. 여러 공급자·모델 중 선택이 필요하면 `needs_selection`과 허용된 선택지를 반환하고 작업을 시작하지 않습니다. 웹 채팅 서비스 이름으로 실행 공급자를 추측하지 않습니다.

| 도구 | 역할 |
| --- | --- |
| `list_projects` | 허용된 상위 프로젝트 목록. 프로젝트 전체 허용과 하위 항목만 허용된 부분 접근을 구분 |
| `list_workspaces` | 허용된 워크스페이스와 상위 프로젝트 탐색. `projectId`로 프로젝트 선택 |
| `list_agents` | 최근 작업 상태. `projectId`·`workspaceId`에 ID 또는 정확한 이름으로 범위 지정 |
| `list_providers` | 선택한 워크스페이스에서 사용할 코딩 제공자와 준비 상태 확인 |
| `list_models` | 제공자에서 선택할 모델 확인. 생성에 바로 쓸 `provider/model` 값 반환 |
| `create_agent` | 허용된 프로젝트·워크스페이스에 작업 접수. 필수 입력은 `prompt`, `requestKey`. AI가 새 키를 만들고 같은 요청 재시도에만 재사용 |
| `import_agent` | `mode=native`: 원본 제공자 세션 가져오기. `mode=handoff`: 기록을 인계해 새 에이전트 생성. 두 방식 모두 AI가 `requestKey`를 만들고 같은 의도의 재시도에만 재사용 |
| `send_agent_prompt` | 후속 지시. `agentId`, `prompt`, `messageId` 사용. AI가 키를 만들며 기본 동작은 steer |
| `get_agent` | 기본 `summary`: 상태·최근 도구 활동 최대 10건·변경 파일·마지막 답변 최대 4,000자. `view=messages`: 대화 기록. `view=activity`: 도구 실행·파일 경로·성공/실패·종료 코드의 작업 내역. 두 기록 모두 커서 기반 페이지 조회. `view=status`: 상태만. `waitSeconds=0..20`: 선택적 대기 |
| `cancel_agent` | 허용된 에이전트의 현재 실행 중단 요청. 기록과 수정 파일 보존 |

0.5에서 기존 `get_agent_status`, `get_agent_activity`, `get_agent_result`, `wait_for_agent`를 `get_agent`로 통합했습니다. 웹 채팅이 이전 도구 목록을 보이면 커넥터 목록을 새로고침하거나 채팅에서 커넥터를 다시 선택하세요. 0.6부터 조회 전용 선택과 화면 탭을 없앴으며, 0.6.1에서는 이미 승인된 유효한 OAuth 연결도 작업 제어 하나로 통일합니다. 재연결 없이 기존 토큰을 계속 사용하며 허용 워크스페이스는 유지합니다.

인증된 연결은 9개 도구를 제공합니다. 호출 대상은 연결의 워크스페이스·에이전트 범위로 제한됩니다. 워크스페이스가 제한된 연결은 임의 `cwd`로 에이전트를 만들 수 없습니다. 조회 페이지가 비어 있어도 `nextCursor`가 있으면 다음 페이지를 확인하세요. 이름 검색은 페이지 전체를 확인하며 최대 2,000개 범위 내에서 고유성을 확인할 수 없으면 ID 선택을 요청합니다. 재시도 키는 연결별로 분리됩니다.

접수는 완료가 아니며 `idle`도 성공이나 테스트 통과를 뜻하지 않습니다. 변경 파일과 마지막 답변은 최근 페이지의 관측값이며 이전 턴의 답변일 수 있습니다. `get_agent`의 요약은 도구의 원문 인자·출력·추론을 제외합니다. 더 긴 답변이나 과거 기록은 `view=messages`로 조회합니다. 대기 시간이 끝나도 작업을 취소하지 않으며 닫힌 웹 채팅으로 완료 알림을 자동 전송하지 않습니다.

### 원본 세션과 기록 가져오기

`import_agent` 하나로 두 방식을 선택합니다. 같은 세션에 메시지만 더하려면 기존 `send_agent_prompt`를 사용합니다. 보관된 Paseo 작업은 `list_agents(includeArchived=true)`로 찾고 ID 또는 고유한 정확한 이름으로 지정합니다. 원본 가져오기가 실패해도 새 세션 생성으로 자동 대체하지 않습니다.

- **원본 가져오기 (`mode=native`)**: Paseo 작업은 `sourceAgentId`로, 외부 제공자 세션은 `sessionId`·제공자 ID `provider`·원본의 절대 경로 `cwd`로 지정합니다. 이미 활성 상태로 가져온 세션은 기존 에이전트를 반환합니다. 보관된 세션은 CLI와 제공자가 지원하고 원본 기록이 남아 있을 때 복구합니다. 모델을 바꾸거나 세션을 복제하지 않으며 프롬프트도 보내지 않습니다. 후속 작업은 `send_agent_prompt`로 전달합니다. CLI 호출은 해당 설치의 명시적 `--home`으로 고정합니다.
- **접근 범위 제한**: 현재 Paseo 0.11.2의 공개 SDK에는 가져오기 API가 없고, CLI 가져오기는 정확한 워크스페이스 ID를 지정할 수 없습니다. 경로만으로 원본 세션의 소유 범위를 확인할 수 없으므로 원본 가져오기는 **호스트 전체 허용 연결에서만** 실행합니다. 프로젝트·워크스페이스 전체 권한도 이 조건을 대신하지 않습니다. 기존 연결 권한을 자동으로 넓히지 않습니다.
- **기록 인계 (`mode=handoff`)**: 웹 채팅 AI가 `get_agent`의 대화·작업 내역을 읽고 목표·결정·변경·검증·남은 일·읽지 못한 기록을 `handoffSummary`로 정리합니다. `sourceAgentId`, 현재 요청 `prompt`, 요약과 선택적 대상 `workspaceId`·제공자/모델 `provider`를 전달합니다. 대상은 기본적으로 원본 워크스페이스입니다. 서버는 최근 타임라인 최대 100항목에서 허용된 메시지·작업 메타데이터를 최대 24,000자까지 추가하고 부분 기록·누락·잘림 여부를 표시합니다. 원본 에이전트는 변경하지 않고 출처를 새 에이전트의 라벨에 남깁니다. 원문 도구 입출력·명령·추론·제공자 설정은 복사하지 않습니다.
- **인계 권한과 한계**: 원본의 조회 권한과 대상의 생성 권한을 각각 검증하며, 에이전트만 허용한 대상에는 새로 만들 수 없습니다. 준비 중 접근 범위나 실제 소속이 바뀌면 생성을 중단합니다. 파일·브랜치·워크트리·제공자 내부 상태는 복원하지 않습니다. 새 에이전트는 현재 파일과 과거 검증 결과를 다시 확인하도록 지시받습니다. 요약은 웹 채팅 AI가 작성하며 완전한 세션 복제를 보장하지 않습니다.

동시 원본 가져오기는 호스트 안에서 제공자/세션별로 직렬화하고 먼저 활성 에이전트를 확인합니다. 인계 생성은 연결별로 분리된 멱등 키와 출처 라벨을 사용합니다. 응답을 놓쳤으면 목록을 확인하고 같은 요청 키로 재시도합니다. 오류가 났다고 임의로 새 요청 키를 만들어 반복 생성하지 않습니다. 인계된 기록은 새로 선택한 코딩 제공자에게도 전달됩니다.

### 대화와 작업 내역 조회

“그 에이전트와 나눈 대화 보여줘”는 `get_agent(view=messages)`, “그 에이전트가 어떤 작업을 했는지 보여줘”는 `get_agent(view=activity)`로 조회합니다. 도구를 더 추가하지 않고 같은 에이전트 ID 또는 정확한 작업 이름으로 구분합니다. 조회한 대화와 작업 내역을 바탕으로 웹 채팅 AI가 요약하고, `send_agent_prompt`로 후속 지시를 보낼 수 있습니다.

두 기록은 `limit=1..100`개의 타임라인 항목을 읽은 뒤 필요한 종류만 추립니다. `scannedEntries`는 읽은 원본 항목 수이며 결과가 비어도 기록 전체가 없다는 뜻은 아닙니다. `hasOlder=true`면 `startCursor`와 `direction=before`, `hasNewer=true`면 `endCursor`와 `direction=after`로 다음 페이지를 조회합니다. 한 페이지를 읽고 전체 기록을 확인했다고 말하지 않습니다. SDK의 `reset`, `staleCursor`, `gap`도 그대로 전달하므로 기록이 초기화되거나 빠진 경우에는 최신 페이지부터 다시 확인합니다.

대화에는 사용자·에이전트 메시지 본문과 시각·턴·순서 정보를, 작업 내역에는 도구명·작업 종류·상태·시각·턴·순서를 제공합니다. 파일 읽기/수정/쓰기의 경로와 셸 실행의 숫자 종료 코드를 포함하지만 셸 명령·원문 도구 인자·출력·소스 본문·추론은 작업 내역에 넣지 않습니다. `touchedFiles`는 조회한 페이지에서 수정·쓰기가 관측된 파일이며 Git diff나 전체 변경 목록이 아닙니다. 실패 상태는 테스트 통과의 증거가 아니며 원문 오류는 Paseo에서 확인합니다. 기존 호스트·프로젝트·워크스페이스·에이전트 접근 범위를 그대로 적용합니다.

## 연결별 접근 범위

**Connections → 연결된 채팅 → Access**를 눌러 같은 페이지에서 프로젝트 → 워크스페이스 → 에이전트를 펼쳐 선택하고 저장합니다.

- **프로젝트 전체 허용**: 현재·앞으로 만드는 하위 워크스페이스와 모든 에이전트 포함
- **워크스페이스 전체 허용**: 해당 워크스페이스의 현재·새 에이전트 포함
- **에이전트 선택**: 그 워크스페이스에 속한 해당 에이전트만 허용. 이 선택만으로는 새 에이전트를 만들 수 없음

채팅의 `list_projects`도 이 설정을 따릅니다. 프로젝트 전체를 허용하면 `full`, 특정 워크스페이스·에이전트만 허용하면 상위 프로젝트를 `partial`로 표시합니다. 부분 접근에서는 형제 항목·프로젝트 경로·전체 개수를 공개하지 않으며 새 작업 생성 권한도 늘어나지 않습니다. 워크스페이스가 없는 프로젝트는 프로젝트 전체 허용 시에만 조회됩니다. `list_workspaces`, `list_agents`, `create_agent`에 프로젝트 ID나 고유한 프로젝트 이름을 지정할 수 있습니다. 같은 이름의 프로젝트·워크스페이스는 허용된 후보 안에서 선택하며 빈 프로젝트에서 워크스페이스를 자동 생성하지 않습니다.

A 프로젝트 전체와 B 프로젝트의 특정 에이전트처럼 섞어서 선택할 수 있습니다. 상위에서 허용한 하위 항목에는 **상위에서 허용**을 표시합니다. 상위 선택을 끄면 별도로 선택해 둔 하위 규칙만 남습니다. 전체 프로젝트 허용은 이 호스트의 모든 항목을 포함합니다. 최대 100개 규칙을 저장합니다.

저장한 변경은 기존 토큰에 바로 적용되므로 재연결할 필요가 없습니다. 진행 중인 작업을 중단하지는 않습니다. 프로젝트 소속은 Paseo SDK의 현재 ID로 확인하며 이름·경로로 추측하지 않습니다. 동시에 편집하면 먼저 저장된 변경을 보존하고, 늦은 저장은 다시 편집하도록 안내합니다. 조회·대기 중 접근 범위나 프로젝트 소속이 바뀌면 이전 범위의 결과를 전달하지 않습니다. 이 제한은 MCP 호출 범위이며 실행 에이전트의 파일 접근 샌드박스가 아닙니다.

## 저장과 수명

- 플러그인 로드만으로 포트를 열지 않습니다. 중지·리로드·비활성화 시 HTTP 연결을 닫고 진행 중인 OAuth 요청을 폐기합니다. 발급된 연결은 파일에 보존합니다.
- 바인드·포트·비밀키·공개 주소를 변경하면 리스너를 중지합니다. 다시 시작해야 합니다. 키를 바꿔 시작하면 이전 연결의 액세스·갱신 토큰은 모두 차단됩니다.
- 연결 비밀키는 호스트 설정에 저장됩니다. OAuth 상태는 `$PASEO_HOME/plugin-data/paseo-mcp-plugin/oauth.json`에 권한 `0600`으로 저장됩니다. 클라이언트 시크릿은 SDK 인증에 필요해 파일에 저장되며, 액세스·갱신 토큰과 연결 비밀키는 OAuth 파일에 해시만 저장합니다. 디스크 암호화는 별도입니다.
- 수집을 켠 동안 도구 호출의 간단한 성공/오류 기록 50건을 메모리에 유지합니다. 별도로 아래 통신 로그를 호스트에 저장합니다.

## MCP 통신 로그

메인 상단의 **Connections / Logs** 탭으로 같은 페이지 안에서 전환합니다. **Logs** 탭의 **Collection on / Collection off**으로 기록 여부를 선택합니다. **Collection off**은 새 요청·응답의 캡처와 파일 저장, 메모리 호출 이력을 모두 중단하며 진행 중인 응답의 수집도 즉시 해제합니다. 재시작 후에도 선택을 유지하고 기존 로그는 보존합니다. 요청·응답 상세와 연결 이름·ID 및 도구 이름 필터를 사용합니다. 로그는 페이지당 25건이며 이전/다음 페이지로 이동합니다. 탭을 바꿔도 필터와 현재 페이지를 유지하고, 필터 변경·새로고침·전체 삭제 시 첫 페이지로 돌아갑니다. 새 기록은 현재 목록에 자동으로 끼워 넣지 않습니다. 내려받기는 현재 페이지뿐 아니라 필터에 맞는 전체 로그를 포함합니다. 연결 승인 요청은 로그 탭을 보는 중에도 연결 탭의 대기 건수로 알립니다. 필터한 전체 기록이나 단일 기록을 웹에서 JSONL 파일로 내려받을 수 있습니다. 네이티브 앱에서는 개별 기록 공유를 지원합니다. **Delete all logs**는 필터와 관계없이 이 호스트의 저장 기록을 삭제하며, 진행 중이던 요청이 삭제한 기록을 다시 남기지 않습니다. 기록 설정 변경은 MCP 서버 재시작 없이 적용됩니다.

기록은 기본으로 켜져 있으며 `$PASEO_HOME/plugin-data/paseo-mcp-plugin/logs/`에 저장합니다. 디렉터리는 `0700`, 파일은 `0600`이고, 4MiB 단위로 파일을 나눠 최근 7일·총 50MiB까지 보관합니다. 재시작해도 로그와 켜기/끄기 설정을 유지합니다. 저장 실패·큐 초과로 누락된 건수는 현재 실행 동안 화면에 표시하며 로그 오류가 MCP 작업을 실패시키지는 않습니다. 보관 기간·용량 제한에 따른 오래된 기록 정리는 자동입니다.

`/`와 `/mcp`로 오간 초기화·도구 목록·도구 호출·알림·오류의 본문, 시각, 연결 식별자, 처리 시간, HTTP 상태를 기록합니다. OAuth 경로, 인증 헤더, 쿠키, URL 쿼리는 기록하지 않습니다. 미인증 요청은 본문 없이 메타데이터만 남깁니다. 알려진 연결 비밀키·해당 요청의 Bearer 토큰과 토큰·비밀번호·API 키 같은 이름의 필드는 중첩 JSON·문자열에서도 가립니다. 임의의 작업 본문에 포함된 모든 비밀을 탐지하는 기능은 아니며 저장 암호화도 별도입니다.

응답 본문이 1MiB를 넘으면 부분 원문 대신 `body_size_limit` 표시와 크기만 남깁니다. 과도하게 깊거나 복잡한 구조에는 `structure_limit`을 표시합니다. 화면은 각 본문의 앞 32,000자까지만 표시하며 내려받기에는 저장된 전체 내용이 포함됩니다. 통신 로그는 Paseo의 인증된 관리 화면 RPC로만 조회하고 외부 MCP 도구에는 공개하지 않습니다. 로그에 저장되는 범위는 MCP 통신이며 외부 서비스의 전체 채팅 기록이 아닙니다.

## 검증

`npm run typecheck`와 `npm test`로 HTTP MCP·OAuth·권한 범위·재시도·포트 수명을 검증합니다. 자동 테스트의 작업 실행과 두 가져오기 경로는 가짜 Paseo API·CLI 실행기를 사용합니다. 원본 복구·별도 인계 생성·동시 요청·재시도·준비 중 권한 변경을 검증합니다. 실제 제공자의 세션 가져오기·복구와 새 인계 에이전트 실행은 사용자 세션에서 검증하지 않았습니다. 실제 설치에서는 읽기 전용 호출과 승인·해제만 시험하며 사용자 에이전트 작업을 만들거나 중단하지 않습니다.
