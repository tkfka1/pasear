pasear lets web chat control the Paseo agents on your own host through an authenticated MCP server. Start tasks, send follow-up messages, check progress, read conversations and work activity, summarize results, or stop a run. Supported provider sessions can be recovered, or their history handed to a new agent.

The Paseo screen has connections and logs tabs. Start the MCP listener when needed, manage chat connections, and approve access to selected projects, workspaces, or individual agents. Each host has its own listener, settings, and approvals. Switching hosts in Paseo does not redirect an existing chat connection. The interface is currently in Korean; listing screenshots use sample data.

Requires Paseo daemon and app 0.11.2 or later, npm for dependency preparation, and a local paseo CLI for stopping runs and native session import. The CLI and daemon were checked at 0.15.0 on Linux; other operating systems have not been verified. Provide a public HTTPS address through your reverse proxy, load balancer, or Tailscale Funnel. Forward all paths to the listener, including OAuth discovery and authorization. Both the domain root and /mcp accept MCP requests. The default listener is 0.0.0.0:8787; loopback access is available in advanced settings. After a plugin reload, start the listener again.

Connections use OAuth, dynamic client registration, and S256 PKCE. Enter the connection key in the OAuth browser window, then approve the request and allowed targets in Paseo. Access changes and revocation apply without reconnecting. Project or workspace access includes future children; access to individual agents does not permit creating new agents. These limits govern MCP operations, while the coding provider controls its execution sandbox. Native session recovery requires whole-host access and retained provider data. History handoff starts a separate session and does not restore files or branches.

Requested messages and history are sent to the connected web chat; task prompts and handoff context go to the selected coding provider. Work activity omits raw tool input/output and reasoning. OAuth state stays on the daemon host. Traffic recording is enabled by default, with local retention of 7 days up to 50 MiB. The logs tab supports paging, filtering, export, deletion, and disabling collection. OAuth routes and headers are excluded, and known credentials are redacted; arbitrary secrets in task text may remain. Disabling collection preserves existing logs. Log access is limited to authenticated Paseo management.

Official registration guides for Claude, ChatGPT, Gemini, and Grok were checked on 2026-11-05. A user confirmed Claude OAuth connection; full real-account task testing across all four services is incomplete. Availability depends on the service, account, region, and workspace policy. Like other Paseo plugins, pasear runs as trusted local code.
