pasear connects web chat to the Paseo agents running on your own host. Ask for work, switch between agents, send follow-up instructions, inspect progress, read conversations and tool activity, summarize results, or stop the current run. You can also recover supported provider sessions or hand a task summary to a new agent using another provider.

The plugin adds one compact Paseo screen for server status, settings, and chat connections. First-time setup shows the public URL field directly; port, network access, and key replacement stay under advanced settings. Its MCP listener starts only when you press Start and stays off after a plugin reload. Each host runs its own listener, settings, and connections. Switching the management screen to another host does not redirect an existing chat connection.

Requires Paseo daemon and client 0.11.2 or later, a local paseo CLI for cancellation and native session import, and npm for installation preparation. Configure your own public HTTPS reverse proxy or load balancer, enter its HTTPS domain URL, and register the same URL in your web chat. The domain root accepts MCP requests; existing /mcp URLs and approved connections remain supported. Forward all paths to the listener so OAuth discovery and authorization are reachable too. The listener defaults to 0.0.0.0:8787; loopback-only access is available in advanced settings, and existing saved addresses are preserved. The interface is currently in Korean.

Authentication uses OAuth with dynamic client registration and S256 PKCE. A connection key and explicit approval in Paseo are required. The owner selects allowed projects, workspaces, or individual agents. New agents need creation access to their destination workspace. Native session import currently requires access to the whole host because the CLI cannot select an exact workspace, and depends on provider support and retained session history. History handoff starts a separate session; it does not restore files, branches, or provider runtime state.

Requested messages and history are sent to the connected web chat. Task prompts and handoff context are sent to the selected coding provider. Activity responses exclude raw tool input/output and reasoning; conversation text can still contain sensitive task content. OAuth state is stored on the daemon host. Workspace restrictions limit MCP operations, not the coding provider's execution sandbox. Like other Paseo plugins, this is trusted local code.

Public HTTPS authentication, owner approval, SDK reads, and revocation have been checked. Compatibility with each web service depends on its account, plan, region, and connector support; full real-account testing across Claude, ChatGPT, Gemini, and Grok is incomplete. Creation and recovery tests use fake APIs and CLI execution. Closing an SDK connection does not stop an agent; stopping a run keeps its history and file edits.
